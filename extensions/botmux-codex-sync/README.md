# Botmux Codex 会话同步

在 VS Code Remote SSH 的远端安装此扩展，资源管理器里会自动出现 **Botmux 会话**。按机器人分组发现其托管会话及已绑定的原生 Codex 会话；点击打开过程面板，可直接追问原会话。

这是与原生 Codex 扩展并存的同步入口，不修改 OpenAI 扩展、不合并 CODEX_HOME、不复制或改写原始会话文件。原生 Codex 窗口仍可操作自己库里的会话；Botmux 面板负责跨库发现和过程跟随。

- 会话列表每 3 秒刷新，打开的过程面板每 1 秒读取新增事件。此为轮询周期，不是端到端时延保证。
- 原生会话追问优先路由到现有 Codex owner；没有 owner 时由 Botmux 后台恢复同一 thread。Botmux 托管会话始终交给原 worker，冷恢复不新建会话。
- 每次提交有持久请求 ID，多个面板按会话串行提交。未确认的请求不自动重发；若提示结果不确定，先检查历史，避免重复执行。
- 显示用户原文、公开进展、工具名称和完成状态、最终回答；不展示模型私有推理、系统提示、完整工具参数或凭据。
- 断线自动重连，从游标补齐。后台保留最近 1000–2000 条公开过程事件用于面板跟随；更早过程保留在原生记录中，累计统计读取全部可用记录。
- 统计使用项目已有的分块 UTF-8 JSONL 扫描器和字节游标；无新增运行依赖。日志是持久来源，重启后可重建，同一进程仅折叠新增记录，未变化的文件只做 stat。
- 累计运行是执行轮次的实际墙钟时长（含模型、工具及轮内等待，不含轮间空闲），不是 CPU 时间；缓存 Token 已包含在输入 Token 中，不再加到总量。未报告的用量显示 `—`，缺失历史显示“可用记录”。卡片运行中每 15 秒更新，空闲每 60 秒更新，正常输出也会触发更新。

扩展仅连接远端机器本地的 Botmux IPC。默认 data 目录 `/home/ubuntu/my/botmux/data`，可配置 `botmuxSync.dataDir`。机器人身份和执行权限沿用该机器已有 Botmux 会话。
