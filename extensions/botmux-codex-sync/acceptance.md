# 5090 交叉验收

验收可用的话题是「获取 SSH 公钥配置」现有续聊绑定。重要 SIENN-1 原会话只允许检查路由与可读性。保留迁移原档、固定测试分支和现有话题归属，验收不生成新分支。

| 场景 | 需要验证 |
|---|---|
| VS Code 入口 | Mac 通过 Remote SSH 连接 dev5090，右侧边栏能打开会话、查看历史、回到底部，并用 Enter 发送、Shift+Enter 换行。使用 Botmux 的独立视觉样式。 |
| Botmux 独立 | VS Code 退出时，飞书话题仍能向 5090 的持久进程投递，能收到进度和结果。 |
| VS Code 独立 | 不依赖 Botmux 的本地 HTTP 服务，扩展经 5090 私有 socket 向进程代理提交和读取。Botmux 恢复后从日志补齐同步。 |
| 双向同步 | 从两端分别提交，核对原会话 ID、请求 ID、轮次 ID、进度和回复。两端查看同一结果。 |
| 长任务 | 用测试话题运行超过 60 秒的确定性等待，验证执行中状态不会误报空闲或结束。 |
| 并发追问 | 长任务期间从两端分别追加追问。每条只入队一次，按入队顺序开始，同一时刻只有一个写入轮次。 |
| 离开与回来 | 在长任务执行中关闭测试窗口。5090 进程继续运行，Botmux 继续同步。重新打开扩展后读取同一轮进度和最终回复。 |
| 重连与超时 | 重发同一请求 ID 不产生第二轮。回执不明时等待精确客户端 ID，不按文字猜测提交结果。 |
| 保护边界 | 记录历史前缀哈希和其他机器人 PID；测试内容不访问 SSH 配置或密钥，不修改项目文件。 |

报告中分开记录本地模拟验证与线上实测，失败保留请求编号和状态，沿同一请求继续核对。
