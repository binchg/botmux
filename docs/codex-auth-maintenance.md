# Codex 共享认证与凌晨刷新

同一台机器、同一账号的 Botmux 实例可以共享 `auth.json` 和 `auth.lock`，
各自的 `CODEX_HOME`、模型、配置和会话仍独立。配置共享前必须核验账号一致，
保留权限为 `0600` 的原认证备份；不要把旧认证复制成多个独立刷新源。
不同账号不合并，不通过此机制向其它主机传送凭据。

每天北京时间 04:00 后的首个维护 tick 执行一次主动刷新（最多约五分钟调度偏差）。
04:00–07:00 内失败后隔十五分钟重试；忙碌会话不会阻止刷新。
Linux 刷新子进程按认证文件的真实路径获取内核 `flock`，竞争者立即退出；
进程异常退出由内核释放锁，不按 PID 删除锁文件。状态文件也按真实认证路径隔离，
因此共享认证只刷新一次，独立登录不会互相跳过维护。

维护进程调用 Codex 官方 `account/read` 的 `refreshToken`，不创建线程或模型轮次，
不占会话名额。它从真实认证目录运行，避免原子替换写断认证符号链接。
`requiresOpenaiAuth` 表示提供方需要认证，不能用它判断用户是否已经登录。
成功必须同时有账号回执及更新后的令牌有效期。

刷新完成不批量重启空闲 App Server。每个会话在下一轮开始前检查认证版本，
等待旧进程退出后恢复原线程；正在执行的轮次不被中断，会话容量配置不变。
维护状态位于 `~/.botmux/codex-auth-maintenance/domains/*/state.json`，
只记录时间、结果和错误分类。令牌值不得进入日志、提交或共享记忆。
